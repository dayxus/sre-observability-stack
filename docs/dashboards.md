# What each panel answers

Three dashboards, all provisioned from `grafana/dashboards/*.json`. Nothing here is
clicked into a UI: a panel exists because a question exists, and the question is written
down in the panel description and in this file. `tests/test_dashboards.py` fails the build
if a panel is not documented here.

Every query reads either a raw metric scraped by this stack or a recording rule from
`prometheus/rules/recording.rules.yml`, and every metric name is listed with its source in
`tests/metric_inventory.json`.

## SLO overview — synthetic availability and latency

`grafana/dashboards/slo-overview.json` · uid `sre-slo-overview` · default home dashboard

| Panel | Operational question | Metric / source |
| --- | --- | --- |
| Error budget remaining (30d) | How much of the 30 day availability budget do we still have? | `slo:availability:budget_remaining_ratio` (recording rule over `probe_success`) |
| Availability SLI (5m) | Is the service available right now, and how far from the 99.5% objective? | `probe_success` from the blackbox http probe |
| Burn rate (5m) | Are we spending budget faster than the objective allows at this moment? | `slo:burn_rate:5m` |
| Burn rate — short against long window | Is this a spike or a sustained trend? | `slo:burn_rate:5m`, `1h`, `30m`, `6h`, `1d` |
| Alerts firing right now | Is anything actually alerting while I look at this? | `ALERTS` (generated by Prometheus from the alerting rules) |
| Availability SLI by probe job | Which probe layer is failing when the average still looks fine? | `lab:probe:success_rate5m` over `probe_success` |
| Latency SLI — requests served under 300 ms | Are we inside the latency objective across 5m, 1h, 6h and 1d? | `slo:latency:ratio_rate{5m,1h,6h,1d}` over the target's duration histogram |
| Burn rate by window | Which window is burning, so I can pick the matching alert and runbook? | `slo:burn_rate:{5m,30m,1h,2h,6h,1d,3d}` |

## Golden signals — synthetic target and node

`grafana/dashboards/golden-signals.json` · uid `sre-golden-signals`

| Panel | Operational question | Metric / source |
| --- | --- | --- |
| Traffic — request rate by path | How much traffic is the workload serving, and which endpoint dominates? | `lab:requests:rate5m` over `synthetic_http_requests_total` |
| Errors — 5xx ratio by path | Which endpoint is returning errors, and is it the injected one? | `lab:errors:ratio_rate5m` |
| Latency — p50, p95 and p99 | What does the tail look like, not just the average? | `synthetic_http_request_duration_seconds_bucket` via `histogram_quantile` |
| Latency — probe duration by job | Do the external probes agree with the workload's own view of latency? | `probe_duration_seconds` (blackbox exporter) |
| Traffic now (5m) | One number for "how busy is this" when reading an alert? | `lab:requests:rate5m` |
| Requests in flight | Is concurrency rising while throughput is flat (saturation signature)? | `synthetic_http_inflight_requests` |
| Saturation — node CPU busy | Is the node running out of CPU headroom? | `node_cpu_seconds_total` (node exporter) |
| Saturation — root filesystem used | Will the TSDB or the Loki chunks run out of disk? | `node_filesystem_{avail,size}_bytes` (node exporter) |

## Blackbox probes — path, transport and TLS

`grafana/dashboards/blackbox-probes.json` · uid `sre-blackbox-probes`

| Panel | Operational question | Metric / source |
| --- | --- | --- |
| Probes up | How many probe layers are green right now? | `probe_success` |
| Probes configured | Did a probe job silently disappear from the scrape config? | `probe_success` series count |
| Certificate expires in (days) | When does the TLS chain break? | `probe_ssl_earliest_cert_expiry` (blackbox ssl module) |
| Probe success by job | Which specific layer — http, tcp, icmp or ssl — is failing? | `probe_success` per job |
| HTTP phase breakdown | Is the time going to DNS, connect, TLS, processing or transfer? | `probe_http_duration_seconds` by `phase` |
| HTTP status code returned by the probe | What did the endpoint actually answer? | `probe_http_status_code` |
| Exporter scrape health | Is the probe failing, or is the exporter unreachable? | `up` for the blackbox jobs |
| Probe results — current state | A single table to read during an incident: every probe, every target, now? | `probe_success` |

## Reading them together

1. `TargetDown` or `ProbeFailing` → open **Blackbox probes**, check `Probes configured`
   first: a missing job and a failing job look identical on an average.
2. SLO alert → open **SLO overview**, read the window that is burning, then follow the
   `runbook_url` carried by the alert itself.
3. Latency or error complaints without an alert → open **Golden signals** and compare the
   workload's own percentiles with `probe_duration_seconds`: if they diverge, the problem
   is outside the process.
